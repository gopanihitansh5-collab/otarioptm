## Verdict

The two halves **do** talk: all 8 HTTP routes + the WebSocket that the web app calls exist with compatible methods, and the live handshake (`initial budget snapshot -> pong -> workflow.started -> snapshot`) was executed successfully against the running app. 28/28 backend tests pass, `tsc --noEmit` and `eslint` are clean, and the Docker/Compose wiring is internally consistent.

What is not true is the **documented** contract. The highest-severity findings are (a) the SSE section of `docs/api.md` describes a format the gateway never emits, (b) the router's health signal is both mis-scaled (`/5`) and sign-flipped, so the advertised "cheapest-**healthy** model" routing is really "cheapest model, health ignored (or anti-weighted)", and (c) the WebSocket pong payload carries a budget snapshot the client structurally cannot read.
